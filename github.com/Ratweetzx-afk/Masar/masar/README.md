# مسار (Masar) — دليل التشغيل الكامل

موقع وتطبيق (PWA) لعرض حالة رحلات مطارات جدة والرياض والدمام، مبني بالكامل على خدمات مجانية. هذا الدليل موجّه لشخص غير مبرمج، خطوة بخطوة، من جوالك أو حاسوبك.

---

## ⚠️ نقطة مهمة جداً قبل البدء — اقرأها أولاً

هذا الموقع **لا يعرض بيانات لحظية حقيقية**. البيانات تُحدَّث تلقائياً **مرة واحدة يومياً** لكل مطار (+ إمكانية تحديث يدوي محدود بـ3 مرات/يوم من لوحة الأدمن). هذا قرار متعمد لسبب واحد: الباقة المجانية من مصدر البيانات (AeroDataBox) تسمح بـ600 "وحدة" شهرياً فقط، والحساب المحافظ (بافتراض أسوأ تكلفة محتملة لكل طلب) يسمح بحوالي 90 طلب/شهر فقط بأمان — أي أقل من طلب واحد لكل مطار يومياً بقليل من الهامش.

**لا تُغيّر وتيرة التحديث التلقائي في `refresh-flights.js` أو جدولة Cron قبل قراءة قسم "حساب الاستهلاك" أدناه** — رفعها بدون حساب دقيق قد يوقف الموقع بالكامل في منتصف الشهر عند تجاوز الحد.

---

## الخطوة 1: إنشاء حساب AeroDataBox (مصدر بيانات الرحلات)

1. من جوالك، افتح المتصفح واذهب إلى: **rapidapi.com**
2. اضغط "Sign Up" وسجّل بحسابك (يمكن التسجيل بـ Google مباشرة)
3. في مربع البحث أعلى الصفحة، اكتب: **AeroDataBox**
4. افتح صفحة AeroDataBox، واختر الباقة **Basic (Free)**
5. اضغط "Subscribe"
6. بعد الاشتراك، ستجد في الصفحة قسم "X-RapidAPI-Key" — هذا هو مفتاحك السري. انسخه واحفظه في مكان آمن مؤقتاً (سنحتاجه لاحقاً في Netlify) — **لا تشاركه مع أحد ولا تضعه في أي كود عام**

---

## الخطوة 2: إنشاء حساب Supabase (قاعدة البيانات)

1. اذهب إلى: **supabase.com**
2. سجّل حساباً جديداً (يمكن بـ GitHub)
3. اضغط "New Project"
4. اختر اسماً للمشروع (مثلاً: masar)، وكلمة مرور قوية لقاعدة البيانات (احفظها، لن نحتاجها مباشرة لكن يفضّل حفظها)
5. اختر المنطقة الأقرب (مثلاً Frankfurt أو Bahrain إن متوفرة) واضغط "Create new project" — انتظر دقيقتين حتى يجهز
6. من القائمة الجانبية، اضغط على أيقونة **SQL Editor**
7. اضغط "New query"، افتح ملف `schema.sql` المرفق في هذا المشروع، **انسخ كامل محتواه** والصقه في المحرر، ثم اضغط **Run**
8. بعد نجاح التشغيل، من القائمة الجانبية اذهب إلى **Project Settings → API**
9. ستجد هناك ثلاث قيم مهمة، احفظها جميعاً:
   - **Project URL** (يشبه `https://xxxxx.supabase.co`)
   - **anon public key** (لن نستخدمه فعلياً في هذا التصميم لكن احفظه)
   - **service_role key** ⚠️ **سري جداً — لا تشاركه إطلاقاً** — هذا هو المفتاح الذي سيستخدمه الموقع خلف الكواليس

---

## الخطوة 3: توليد كلمة مرور الأدمن

هذه الخطوة تحتاج تشغيل أمر بسيط مرة واحدة فقط على حاسوبك (أو عبر أي بيئة Node.js مجانية مثل Replit):

1. افتح ملف `scripts/hash-password.js` من هذا المشروع
2. شغّل الأمر التالي (استبدل كلمة المرور بكلمة مرور قوية خاصة بك):
   ```
   node scripts/hash-password.js "كلمة-مرور-قوية-جداً-2026"
   ```
3. سيطبع لك الأمر جملة SQL جاهزة تبدأ بـ `insert into admin_auth...`
4. انسخ هذه الجملة، وشغّلها في **Supabase → SQL Editor** (كما في الخطوة السابقة)

الآن كلمة مرور الأدمن محفوظة بشكل مشفّر (scrypt) — لا يمكن لأحد رؤيتها حتى لو اطّلع على قاعدة البيانات مباشرة.

---

## الخطوة 4: رفع المشروع على GitHub

1. أنشئ حساباً على **github.com** إن لم يكن لديك
2. أنشئ مستودعاً (Repository) جديداً باسم `masar`
3. ارفع جميع ملفات هذا المشروع إليه (عبر واجهة GitHub في المتصفح: "Add file → Upload files"، اسحب كل الملفات والمجلدات)

---

## الخطوة 5: النشر على Netlify

1. اذهب إلى: **netlify.com** وسجّل حساباً (يفضّل بـ GitHub مباشرة لتسهيل الربط)
2. اضغط "Add new site" → "Import an existing project"
3. اختر GitHub، ثم اختر مستودع `masar` الذي رفعته
4. اترك إعدادات البناء كما هي (Netlify سيقرأ `netlify.toml` تلقائياً) واضغط "Deploy"
5. بعد انتهاء النشر (دقيقة أو دقيقتين)، اذهب إلى **Site settings → Environment variables** وأضف المتغيرات التالية واحداً تلو الآخر (Add a variable):

   | الاسم | القيمة |
   |---|---|
   | `SUPABASE_URL` | القيمة من الخطوة 2 |
   | `SUPABASE_SERVICE_ROLE_KEY` | القيمة من الخطوة 2 (السرية) |
   | `AERODATABOX_API_KEY` | القيمة من الخطوة 1 |
   | `SESSION_SECRET` | أي نص عشوائي طويل جداً تختاره بنفسك (32 حرفاً فأكثر، مثال: افتح أي "مولّد كلمة مرور" واستخدم الناتج) |
   | `REFRESH_SECRET` | نص عشوائي آخر مختلف تماماً عن السابق، بنفس الطريقة |

6. بعد إضافة المتغيرات، اذهب إلى **Deploys** واضغط "Trigger deploy → Deploy site" لإعادة النشر بحيث تُطبَّق المتغيرات الجديدة

موقعك الآن يعمل على رابط مثل `https://your-site-name.netlify.app` — يمكنك تغيير الاسم من **Site settings → Change site name**، أو ربط دومين خاص بك مجاناً من نفس الصفحة (Domain management) إن كان لديك دومين.

---

## الخطوة 6: جدولة التحديث اليومي التلقائي (مجاني)

Netlify المجاني لا يدعم جدولة تلقائية (Scheduled Functions) بدون خطة مدفوعة، لذا سنستخدم خدمة مجانية خارجية لتشغيل التحديث مرة يومياً:

1. اذهب إلى: **cron-job.org** وسجّل حساباً مجانياً
2. اضغط "Create cronjob"
3. الرابط (URL): `https://your-site-name.netlify.app/.netlify/functions/refresh-flights`
4. الطريقة (Method): **POST**
5. في "Advanced" → Headers، أضف: `Content-Type: application/json`
6. في "Body"، أضف (لمطار جدة):
   ```
   {"airport": "JED", "secret": "نفس-قيمة-REFRESH_SECRET-التي-اخترتها"}
   ```
7. حدد الجدولة: **مرة واحدة يومياً** (مثلاً الساعة 5 فجراً بتوقيت السعودية)
8. احفظ، ثم **كرّر الخطوات 2-7 مرتين إضافيتين** لإنشاء وظيفتين مماثلتين لـ `RUH` و `DMM` (بفارق ساعة بين كل واحدة، مثلاً 5:00، 5:05، 5:10 صباحاً — لتفادي تصادم الطلبات الثلاثة معاً في نفس اللحظة)

---

## ✅ انتهيت — الموقع يعمل بالكامل مجاناً الآن

افتح `https://your-site-name.netlify.app` للموقع العام، و `https://your-site-name.netlify.app/admin.html` للوحة التحكم.

## حساب استهلاك AeroDataBox بالتفصيل (لماذا "مرة يومياً"؟)

- الباقة المجانية: **600 وحدة/شهر**
- endpoint المستخدَم (FIDS — جدول المغادرات/الوصول) عادة من الفئة **Tier 3 (6 وحدات/طلب)** حسب توثيق AeroDataBox — لسنا متأكدين 100% حتى تبدأ الاستخدام الفعلي
- التصميم الحالي: **طلب واحد فقط لكل مطار يومياً** (تلقائي) = 3 طلبات/يوم × 30 يوم = **90 طلباً/شهر**
- بافتراض أسوأ سيناريو (6 وحدات/طلب): 90 × 6 = **540 وحدة من أصل 600** (هامش أمان 10%، يغطي التحديثات اليدوية الاستثنائية)
- بعد أسبوع من التشغيل الفعلي، افتح لوحة RapidAPI الخاصة بك (**My Apps → AeroDataBox → Analytics**) لترى الاستهلاك الحقيقي بالضبط

### إذا تبيّن أن التكلفة أقل من المتوقع (Tier 1 = وحدة واحدة/طلب)
عندها لديك هامش كبير جداً (600 بدل ~100). يمكنك رفع وتيرة التحديث التلقائي بأمان — مثلاً كل 4 ساعات بدل يومياً — بتعديل عدد وظائف cron-job.org لتكرار الاستدعاء لكل مطار عدة مرات يومياً بدل مرة واحدة. **لا تفعل هذا قبل التأكد من الاستهلاك الفعلي من لوحة RapidAPI.**

## ⚠️ أي ميزة مستقبلية ستحتاج تجاوز المجاني؟

- **إشعارات Push للرحلات** (تنبيه المستخدم عند تغيّر حالة رحلته): تحتاج إما خدمة AeroDataBox's "Flight Alert" (نظام رصيد منفصل، ليس ضمن الباقة المجانية الحالية) أو بنية تحتية إضافية لإدارة الاشتراكات — هذه ميزة يجب التوقف عندها واستشارتي مجدداً قبل البناء، لأنها كما هو مذكور في توثيق AeroDataBox تتطلب تحويل وحدات من رصيدك إلى "أرصدة تنبيهات" منفصلة، ما يعني استهلاكاً إضافياً من نفس الحصة الشحيحة أصلاً
- **تحديث أسرع من مرة يومياً بشكل مضمون** (بدون انتظار التحقق من التكلفة الفعلية): يتطلب ترقية AeroDataBox إلى الباقة المدفوعة (Pro بحوالي $5.35/شهر) — لم أُضِف أي كود يعتمد على هذا، فقط أخبرك أنه الخيار الوحيد إن أردت لحظية حقيقية لاحقاً
- **تخزين أكثر من عدد قليل من الإعلانات/الصور**: Supabase المجاني يكفي بسهولة لهذا الحجم، لا داعي للقلق حالياً

## بنية الملفات

```
index.html              — الصفحة الرئيسية
admin.html              — لوحة التحكم
styles.css              — الهوية البصرية الكاملة (لا CSS مضمّن في أي مكان)
app.js                  — منطق الصفحة الرئيسية
admin.js                — منطق لوحة التحكم
manifest.json           — إعدادات PWA
sw.js                   — Service Worker (يعمل بدون إنترنت للواجهة فقط، وليس البيانات)
netlify.toml            — إعدادات النشر + رؤوس الأمان (CSP الصارم)
schema.sql              — قاعدة البيانات الكاملة (شغّله مرة واحدة في Supabase)
scripts/hash-password.js — توليد كلمة مرور الأدمن (يُشغَّل محلياً مرة واحدة)
netlify/functions/
  get-flights.js         — قراءة عامة (بدون تكلفة API خارجية)
  refresh-flights.js     — الوحيد الذي يتصل بـ AeroDataBox
  search-flight.js       — بحث برقم الرحلة (يبحث في البيانات المخزّنة فقط، بدون تكلفة)
  get-banner.js          — قراءة عامة للإعلان النشط
  admin-login.js         — تسجيل دخول محمي بقفل ذرّي ضد التخمين
  admin-banner.js        — إدارة الإعلانات (محمي)
netlify/lib/utils.js     — أدوات مشتركة (تشفير، تحقق من المدخلات، تعقيم)
icons/                  — أيقونات PWA (جاهزة، مبنية على الهوية البصرية)
```

## ملخص الحماية الأمنية المطبّقة

- مفتاح AeroDataBox لا يظهر أبداً في كود المتصفح — موجود فقط في متغيرات بيئة Netlify، ويُقرأ داخل `refresh-flights.js` فقط
- كل نص خارجي يُعرض عبر `textContent` حصراً في `app.js`/`admin.js` — لا يوجد `innerHTML` في أي مكان بالمشروع، فلا توجد ثغرة XSS ممكنة من بيانات الرحلات أو الإعلانات
- قفل الأدمن ذرّي (Postgres function مع `FOR UPDATE`) — مقاوم تماماً لحالات السباق حتى لو حاول عدة أشخاص تسجيل الدخول في نفس اللحظة بالضبط
- سياسة CSP صارمة بدون `unsafe-inline` إطلاقاً — أي محاولة حقن سكربت داخل الصفحة سيرفضها المتصفح تلقائياً
- كل المدخلات (رمز المطار، رقم الرحلة، بيانات الإعلان) تُتحقَّق بصرامة قبل معالجتها
- حدود حجم الطلبات (5000 بايت لطلبات الإعلانات) لمنع استنزاف الموارد
- Row Level Security مفعّلة على كل الجداول في Supabase كطبقة حماية إضافية حتى لو تسرّب مفتاح بالخطأ
